# Patterns

Reusable architectural patterns that more than one SupaFactory project needs.

A pattern belongs here when it describes **how to build something**, is not
specific to any one product, and would otherwise be re-decided — or silently
diverge — in every project that hits the same problem.

Patterns are reference material, not governance. They do not grant permission,
and adopting one is a project decision. A project records its adoption in its
own decision log as a short entry that names the pattern and the project-specific
values it chose; the pattern itself stays here and is written once.

Pattern IDs use the `SF-P-` prefix so they cannot collide with the `D-` decision
IDs that projects number independently.
